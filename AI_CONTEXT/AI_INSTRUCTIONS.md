# دستورالعمل کار با پروژه Repair برای هوش مصنوعی

این فایل را قبل از هر تغییر در کد بخوان.

## قانون اصلی
تو باید کار را از وضعیت واقعی پروژه ادامه بدهی، نه از حدس یا توضیح کاربر.

## ترتیب بررسی
1. `AI_CONTEXT/PROJECT_CONTEXT.md` را بخوان.
2. `AI_CONTEXT/HANDOFF.md` را بخوان.
3. `AI_CONTEXT/CHANGELOG.md` را بخوان.
4. وضعیت Git و آخرین commitها را بررسی کن.
5. فایل‌های مرتبط با `CURRENT_TASK.md` را بررسی کن.
6. قبل از تغییر، وابستگی‌ها و اثر تغییر روی SQL Server و بخش‌های دیگر برنامه را بررسی کن.

## قوانین تغییر کد
- تغییرات قبلی را بدون دلیل حذف نکن.
- اگر راه‌حل دیگری لازم است، ابتدا کد فعلی را بفهم.
- برای تغییرات بزرگ، مرحله‌ای عمل کن.
- تنظیمات حساس، رمزها و اطلاعات اتصال را داخل Git commit نکن.
- فایل `.env` را commit نکن؛ فقط `.env.example` را به‌عنوان نمونه نگه دار.
- بعد از هر تغییر مهم، تست مناسب اجرا کن.

## پایان هر جلسه
قبل از پایان کار حتماً:
1. `HANDOFF.md` را با وضعیت واقعی به‌روزرسانی کن.
2. `CHANGELOG.md` را با تغییرات انجام‌شده به‌روزرسانی کن.
3. اگر کاری باقی مانده، دقیقاً بنویس مرحله بعد چیست.
4. نتیجه تست‌ها و خطاهای باقی‌مانده را ثبت کن.
5. اگر Git استفاده می‌شود، خلاصه commit یا commit hash را ثبت کن.

## اگر اطلاعات کافی نیست
حدس نزن. مشخص کن چه چیزی باید بررسی شود و ابتدا از کد، Git، فایل‌های Context یا لاگ‌ها اطلاعات لازم را پیدا کن.
